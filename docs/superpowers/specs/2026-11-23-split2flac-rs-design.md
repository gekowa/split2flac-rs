# split2flac-rs 跨平台移植：以原版切轨结果为准

状态：切轨与编解码方案已确认；正式目标为 Windows 与 macOS。下列实测来自原版，不是 Rust 版验收结果。

## 目标与取舍

在 Windows 10/11 x64、macOS Apple Silicon 和 macOS Intel 上提供原生离线 CLI `split2flac-rs`（Windows 为 `split2flac-rs.exe`）。目标是解压后直接运行，不依赖用户安装 shell、Homebrew 或系统 FFmpeg。三个目标共享 Rust 核心，不维护平台版切轨算法。参考对象是 [split2flac v122，491591d](https://github.com/ftrvxmtrx/split2flac/blob/491591d21e2f97419e74751864b76b234b0fa2f1/split2flac)。五种输入（APE、FLAC、TTA、WV、WAV）、六种输出（FLAC、M4A/AAC、MP3、Vorbis、Opus、WAV）和专辑处理功能都在范围内。

- **已选择：Rust 切轨，统一编解码。** Rust 决定取哪份 CUE、取哪些样本、如何命名；FFmpeg 负责音频读写，不负责决定切点。无需用户逐一安装原版工具。
- **未选：逐个移植旧编码器。** 可原样透传旧编码参数，但恢复了用户希望消除的依赖链。
- **未选：用 FFmpeg 的章节或时间戳直接分段。** 少一些代码，但容器章节、时间取整和首轨前音频的处理并不代表原版切轨语义。

要求一致的是原版对同一输入切出的各轨及轨前音频，不是有损编码器的输出字节。不新增 GUI、重新定义的“正确”预间隙模式或独立的通用 CUE 编辑器。

## 切轨契约及已知证据

上游先用 `cueprint` 读取轨数和标签、用 `cuebreakpoints` 对轨数做检查；真正切轨时把 CUE **文本**交给 `shnsplit`。单轨另走 `shncue` 路径。因此不能仅实现一个 `INDEX 01 × 采样率 / 75` 的公式，也不能把 `cuebreakpoints` 的输出当作真值。

参考环境为 `linux/amd64` 镜像 `mikenye/split2flac@sha256:47e6cb8d835a05f08efae20f7bf196552754df09e9dc957cc473b870f4dbc8ba`，直接调用 `/split2flac/split2flac`，不经过镜像入口脚本。镜像脚本与上游脚本 SHA-256 相同：`9150d8ccc6a47e0ea35bcdd4d5c790ce03c8cb70302f64a5512d7f78e0e79822`。工具版本：shntool 3.0.10，cuetools 1.4.0。镜像仅用于产生参考结果，不是发布依赖。

实测输入为双声道 16 位 WAV，每个 PCM 采样帧编码自己的序号，长度为两秒加 17 帧；轨号从 1 起，源样本序号从 0 起。

| 输入 | 原版观测 |
| --- | --- |
| 44.1 kHz，第二轨 `INDEX 00 00:00:70`、`INDEX 01 00:01:01` | 第一轨 44,688 帧，第二轨从 44,688 开始、长 43,529 帧；间隙在前轨 |
| 相同 CUE，48 kHz | 第一轨仍是 44,688 帧，第二轨长 51,329 帧；不是按 48 kHz 换算出的 48,640 |
| 44.1 kHz，第一轨 `INDEX 01 00:00:05`，第二轨如上（无 INDEX 00） | 另有 `00.wav`，保存源开头 2,940 帧；两条命名轨从 2,940、44,688 开始 |
| 44.1 kHz，单轨，起点 0 | 一轨保留全部 88,217 帧，不截掉不足一扇区的尾部 |
| 第二轨标为 `MODE1/2352`、有合法 INDEX，输入仍是同一个 WAV | 此样例退出 0 并写两轨；不能看到非 AUDIO 就一律拒绝 |
| 三条 INDEX 01 依次为 `00:00:00`、`00:01:01`、`00:01:00` | 退出 3；不能排序后假装成功 |

另一组长度为三秒的实测，第二轨同取 `00:01:01`：96 kHz/24 位/立体声切在 29,792 帧，44.1 kHz/16 位/单声道切在 89,376 帧。两者与上表的 44,688 帧都落在解码后第 178,752 字节（76 × 2,352），但每个 PCM 采样帧占用的字节不同。切点等于文件末尾时，44.1 kHz/16 位/立体声双轨样例退出 3，留下完整的第一轨；超出末尾一帧时同样退出 3，但没有输出轨。含第二个 `FILE` 且两条 `INDEX 01` 都为零的样例在轨数检查处退出 3。

这些是具体样例，不据此猜测未对齐字节应如何取整。混合数据轨、多 FILE、坏时间和其他音频布局均用固定参考环境逐例定性。保持原版支持边界，不把多文件拼接等扩展作为“兼容”。

## 处理路径

1. Rust 保留原 CLI 的输入、递归、别名、配置保存、dry-run、退出码与失败清单。配置作为数据解析，不执行 shell。先用显式 `-cue`，否则依次找 `album.flac.cue`、`album.cue`，再查原版支持的内嵌来源（FLAC 的文本 CUESHEET、WV、APE）。保持字符集显式指定、检测及交互/`-nask` 路径；探测器的参数不能静默忽略。
2. 将 CUE 解析为专辑字段、轨字段与有序索引；分开处理读标签、轨数预检查和真正的分界。以解码后 PCM 的整数字节偏移表示原版分界，检查算术溢出、顺序和 EOF，不把分界擅自取整到整秒、扇区或完整采样帧。包括原版另存的轨前文件。
3. 随包的 `ffprobe` 探测音轨及精度，`ffmpeg` 只顺序解码一次；Rust 以有界缓冲将每段送入编码器。对落在采样帧中间的旧式 WAV 切点，输出保留原版的音频负载字节及长度；不把编码器对齐用的补零写进最终 WAV。支持的无损表示保留声道、采样率和有效位深；有损编码所需的格式转换在切轨后进行。
4. 保留原命名模板、合辑 performer 回退、分格式元数据、封面搜寻/缩放/嵌入、附属文件复制、配置和批处理。用 `std::path::Path`、`OsStr` 和进程参数数组，不用 shell 插值。两个系统都保留合法 Unicode；仅 Windows 对保留名及该系统禁用的字符另作转义。目标冲突、编码或标签失败时不删除原件；源删除只在整个专辑成功并获 `-D` 对应授权后执行。`-F` 不表示允许覆盖输出。

**冲突规则**：按目标卷实际文件名语义判定是否等价（含 Windows 保留名转义后的重名、macOS 卷的大小写及 Unicode 等价规则）。两个输出互相冲突或目标已存在时，在写出第一轨前失败；单张退出 3，递归时记入失败清单并继续。既不覆盖也不自动加后缀，包括预检后出现的新文件。

## 依赖与编码兼容边界

| 原版职责 | 两个平台的实现选择 |
| --- | --- |
| shntool、cuetools、shell 文件操作 | Rust 实现本程序用到的行为，终端用户无需安装这些程序 |
| flac/flake、mac、ttaenc、wavpack、faac、lame、oggenc、opusenc | 各目标随包提供锁定版本、架构匹配的 `ffmpeg` 和 `ffprobe`；用真实媒体验证五入六出，而非只检查编译参数 |
| metaflac、mp4tags、ID3/Vorbis 工具、ImageMagick | 按容器使用 FFmpeg 或 Rust 元数据读写；封面与标签由独立读取结果验收 |
| iconv、enca | Rust 做转码/探测；用旧编码样例验证 CUE 文本、文件名和标签不乱码 |
| metaflac ReplayGain、vorbisgain、mp3gain、aacgain | 复现分析和写标签，不做音量归一化。`metaflac --add-replay-gain` 和 `vorbisgain -a` 按专辑分组；裸 `mp3gain` 写 APEv2，裸 `aacgain` 对 M4A 写 MP4 自由形式标签，均不指定应用帧增益。Opus/WAV 不处理。单轨和两条响度不同的曲目分别对照标签、音频数据及专辑分组；缺少合适原生构建的功能用可复用的 Rust 实现 |

增益工具来源：[Xiph metaflac](https://xiph.org/flac/documentation_tools_metaflac.html)、[VorbisGain](https://sjeng.org/vorbisgain.html)、[MP3Gain](https://mp3gain.sourceforge.net/download.php)、[AACGain 2.0.0 Windows AMD64](https://github.com/dgilman/aacgain/releases/tag/2.0.0)。AACGain 可作为 MP3/M4A 共用工具的候选，但不能仅凭同源断言其产物等价。原脚本的通配符会把输出目录里已有的同格式文件也送入分析；本移植只处理本次专辑的文件，避免改写不相关的音乐。该差异不改变切点。

`-e` 仍可调编码器、`-eh` 显示当前编码器帮助；此次设计选择 FFmpeg 编码选项作为新语法。随包给出原版默认与常见配方对照，读取旧配置时识别原默认参数；不能对应的旧参数明确报错并给出迁移提示，不静默忽略。旧编码器的任意私有参数、压缩码流逐字节一致性不列为兼容要求。

Windows x64、macOS Apple Silicon 和 macOS Intel 都从同一套锁定源码构建 FFmpeg、ffprobe 和所需的编解码库。源地址、SHA-256、许可证及目标归档格式见 `packaging/tools.lock.json`；压缩包内附对应源码、编译参数和许可证。构建期可预取，运行时不下载，不复制开发机的 Homebrew 程序。未采用第三方预编译包，避免将其未锁定的动态库带入分发包。

Windows 核验 PE 架构和 DLL 导入；macOS 分架构打包，核验 Mach-O 与 dylib 导入。不得把在 Apple Silicon 通过 Rosetta 运行的结果作为 Intel 原生验收。实际验证环境以验收日志为准。

## 验收：先取得独立答案，再验证 Rust

- **基准来源**：生成可重建的非静音 PCM，边界前后样本不同；将同一组音频镜像和 CUE 交给未经修改的固定版脚本。在隔离目录以固定 locale、干净 HOME 和同组 CLI 参数运行。保存输入摘要、工具版本、退出状态、所有产物的相对路径和轨信息，含 `00.*` 和意外多出的轨。参考清单只能由原版生成；Rust 运行不能改写期望结果。基准切轨使用 WAV 输出以隔离编码器与标签工具；参考镜像未安装 `mp4tags`，不能把它的 M4A 标签失败当作原版功能。若对照 M4A 标签，使用另行锁定并补齐 `mp4tags` 的参考环境。
- **无损断言**：对每个 WAV/FLAC 输出读取采样率、声道、有效位深、采样帧数及按约定字节序排列的交错 PCM SHA-256。每轨逐项一致，包括首尾、额外轨和间隙；对于原版完整保留输入的样例，再按顺序拼接对照源 PCM。以音频数据而非容器头、填充或文件大小判等。
- **覆盖矩阵**：普通多轨、单轨、首轨非零、`INDEX 00/01/02`、`PREGAP/POSTGAP`、一帧之差、74 帧进位、非整扇区尾部；不同采样率/位深/声道；显式/自动/内嵌 CUE 与冲突优先级；UTF-8/BOM、旧中文编码、CRLF、空格及合辑；不同 FILE 段、数据轨、缺失/重复/倒序/越界索引。错误样例也要从原版取证，并比对退出码与结果，不预设所有边界情况都失败。
- **编解码与外围功能**：五种输入各用实际媒体覆盖解码。六种输出均检查可解码性、音轨顺序、文件名、格式支持的标签与封面。对有损输出，先验送入编码器的 PCM 边界和哈希，再单独验输出格式、延迟/填充与轨身份；不设虚假的有损 PCM 相等要求。另测配置、递归失败清单、增益、输出冲突和失败不删原文件。
- **发布门槛**：Linux 用来重建上游基准。Windows x64、macOS arm64、macOS x86_64 各自在对应原生环境解压自己的包，从含中文与空格的路径、在没有系统音频工具的条件下运行同一份清单（含 PREGAP、POSTGAP、INDEX 00）、格式测试和失败用例。任何平台都不另设切点容差。交叉编译、模拟器或只显示 `--help` 不算原生验收。
